五个评审剧本 —— 原型必须能一屏走完

业主来电说「主卫漏水」

客服搜手机号 13800138001 → 命中张建国 → 看到 2 套房 + 1 车位、欠费 ¥2,031、1 条在途工单 WO20260001（处理中）→ 点「新建工单」，房号与业主信息自动带入 → 选「入户维修 · 水管漏水」→ 系统给出预估费用区间

业主到前台交费

收银台搜「13800138001」→ 出业主卡片：2 套房 3 笔待缴 → 跨房产勾选合并结算 → 一次收款 ¥2,031.01，票据按房号分行 → 打印

业主要换绑车牌

业主 360 → 车位卡「川B·SFV7D 到期 2026-10-26」→ 点换绑 → 填新牌 → 校验占用 → 提交审批 → 审批通过下发车场 → 显示厂商回执

催缴逾期大户

欠费台账筛「逾期 > 180 天」→ 命中李秀兰（逾期 189 天，¥3,390）→ 生成催缴任务 → 短信 + 电话留痕 → 升级停服审批

巡检发现问题转工单

保洁日检 → 电梯轿厢环节「异常」→ 拍照 + 描述 → 一键转工单 → 工单来源标记「巡检」→ 进度回写任务卡片

验收标准：这五个剧本任何一条需要「切到别的菜单才能完成」，说明该页面没做完。例如剧本 2 如果需要退出收银台再去收费管理查账单，就是不合格。

4数据口径

口径不一致是评审时最容易吵起来的地方，这里先写死。任何页面出现第二套算法，以本页为准。
指标 / 概念口径为什么
欠费已出账未收款金额（bill.unpaid），不含未出账应收把未来几个月的应收算进欠费，业主一查就吵架
逾期天数按最早一期未缴账期的 dueDate 起算，不是按最后一期否则长期欠费户的账龄被低估
收缴率本期已收 ÷ 本期应收 × 100%，分母含减免与作废分母剔除减免会让收缴率虚高
空置率空置房屋 ÷ 房屋总数，分母不含车位与配套用房车位空置是另一个指标，混算无法指导经营
在册人口按身份证去重，不以「房屋数 × 3」上报一人多房会被重复统计
门禁 vs 车场门禁记人次、车场记车次，两者不能相加量纲不同，相加没有业务含义
设备在线率心跳超时阈值按设备类型区分（摄像头 3min、门禁 5min、表计 30min）统一阈值会让低频上报的表计长期「离线」
房屋总数= 楼栋 × 单元 × 层数 × 每层户数，本数据集 736与项目卡片的 houseCount 必须一致
一人多房收费按业主聚合，票据按房号分行，金额合并计一次业主要求一张票，财务要求分房核算
工单是否超时以 createTime + slaHours 判断，公共区域 24h、入户 12h两类工单响应要求不同

脱敏规则（个人信息保护法硬要求）

const debtOf = (ownerId) =>
  bills.filter(b => b.ownerId === ownerId && b.status !== '已缴')
       .reduce((s, b) => s + b.unpaid, 0)

// 一人多房：王浩然 3 套房
