一、先定体系，再画页面：看板分三层，不能都做成"大屏"

你们已经有费用驾驶舱，现在补资产与物联两个，再加一个办公工作台。如果三张看板各画各的， 最后一定是同一个数字三个口径、同一件事三个入口。所以先立一条主线：不同层级的人，看不同的层。

L1 决策层 · 驾驶舱

看趋势与风险，不看明细

  • 资产驾驶舱（本次新增）
  • 物联驾驶舱（本次新增）
  • 费用驾驶舱（已有）
  • 经营总览：收费率 + 成本 + 满意度
  • 使用者：总经理 / 项目经理，每周 1 次
L2 管理层 · 看板

看异常与排名，可下钻到单

  • 品质看板（C8 已有设计）
  • 工单监控台（C3）
  • 收费看板（B1）
  • 人事看板（本次新增，人力资源首页）
  • 使用者：部门主管，每天 1 次
L3 执行层 · 工作台

只回答"我现在该做什么"

  • 办公工作台（本次新增）
  • 收银台（B2 已有设计）
  • 巡检任务日历（C7）
  • 移动端首页与工作台同源
  • 使用者：一线员工，每天 10 次以上

二、六条统一规则（写进设计规范，评审时逐条对）

一屏原则：首屏最多 6 个 KPI + 4 个图表，其余全部下钻。看板不是报表堆场。
数字可点：每个数字都要能点进明细，且携带当前筛选条件；URL 带参可分享给同事。
口径唯一：指标写进「指标字典」（公式 + 分母 + 取数表 + 负责人），看板与报表共用同一个指标服务，禁止各页面自己写 SQL。
三个筛选器固定：项目 / 时间 / 业态（或子系统）固定在顶部，跨页保持，不要每个卡片各带一套。
数据新鲜度可见：实时类 30s（告警、在场车、门禁），统计类 5min 缓存，财务类 T+0 每小时；页面必须显示"更新于 xx:xx"，接口失败显示上次成功时间，绝不显示 0。
权限即数据：看板按数据权限（项目/楼栋/部门）过滤；薪酬、身份证、银行卡单独授权，查看留痕。

区域与职责

  • ① 问候 + 全局动作：一眼看到今天几件事、几件超时，右上角放最高频动作
  • ② 六宫格 KPI：只放"与我有关"的数字，公司经营指标归驾驶舱
  • ③ 待办中心：审批 / 工单 / 巡检 / 抄送四类聚合，按超时优先排序
  • ④ 快捷入口：按角色预置八宫格，可在工作台设置里改
  • ⑤ 考勤 / 日程 / 公告：每天必看的三张卡，放同一行
  • ⑥ 我的效率：自己的量与时长，不做排名（排名是主管视角）

数据与口径

  • 待办来自 C1 审批 + C3 工单 + C7 巡检，统一待办服务聚合，不允许各模块自己算一套
  • 超时判定：审批按流程节点 SLA，工单按工单 SLA，巡检按班次截止时间
  • 考勤取 C2 日结数据，异常需 HR 确认后才计入"异常"
  • 效率指标按"我经手"过滤，不是部门口径
  • 公告已读状态按人记录，置顶项常驻

交互与规则

  • 点待办直接展开业务详情抽屉，不跳页，减少上下文切换
  • 同流程、金额低于阈值的审批支持批量通过
  • 快捷入口按角色模板：客服 / 工程 / 秩序 / 财务 / 项目经理各一套
  • 首屏 < 1.5s：待办分页 10 条 + 骨架屏，非首屏卡片懒加载
  • 移动端与 PC 同源，工作台就是 App 首页

我做的调整
① 待办里混入工单与巡检——物业一线员工不进审批系统，但每天必须看工单和巡检任务；② 加「团队今日」卡，主管在同一个页面就能看到部门的三率（及时率/完成率/合格率），不用切到看板；③ 快捷入口按角色下发，收银员登录看到的是收银台而不是"起草合同"。

区域与职责

  • ① 筛选区：项目 / 时间 / 业态三段固定，全页联动
  • ② KPI 六项：规模（楼栋/房屋/车位）+ 人（在册人口）+ 质量（空置率/产权办理率）
  • ③ 资产构成 + 使用状态：回答"有什么、现在什么状态"
  • ④ 车位健康度：未绑定 = 收不到管理费，是最容易漏的钱
  • ⑤ 楼栋热力：把空置从数字变成位置，直接指向"该处理哪栋"
  • ⑥ 合同到期 + 风险清单：从"看"到"做"的唯一出口

数据与口径

  • 空置率 = 空置房屋 ÷ 可租售房屋（不含车位、不含配套用房），分母必须写进指标字典
  • 在册人口 = 已认证业主 + 已登记租户 + 家属，按身份证去重
  • 产权办理率 = 已出证 ÷ 已交付
  • 合同剩余天数按自然日，取 A5 合同台账；租约与物业费账单分离统计
  • 热力色阶固定分段（0-3% / 3-8% / 8-15% / >15%），不按当期最大最小值自适应，否则跨月不可比

交互与规则

  • 任一 KPI / 图表可点击下钻到明细，条件随 URL 带过去，可分享给同事
  • 卡片右上角「…」支持显隐配置，不同角色默认卡片不同（招商看合同，工程看房屋状态）
  • 空态给引导动作：没有楼栋就"去建楼栋"，没导入房屋就"下载模板"
  • 支持导出 A3 横版 PDF，供月度经营会直接投屏
  • 所有金额默认不含税，鼠标悬停显示含税口径
参考图（图 1）的可借鉴处与我做的优化
可借鉴
① 顶部 6 张数字卡的信息密度；② 环形图 + 图例的轻量表达；③ 左侧按业务分区的导航；④ 卡片留白与浅灰底，长时间看不累。
优化（针对参考图的 5 个问题）
① 数字卡只有总数、没有变化与结构 → 每个 KPI 加环比或结构说明；② 六个图表全是"当前值"，没有一个指向动作 → 增加风险清单与合同到期；③ 没有筛选层级 → 固定项目/时间/业态三段筛选并跨页保持；④ 空置只是数字 → 增加楼栋热力，定位到具体楼栋；⑤ 混入"社区通知/投诉统计"，那是品质与工单域的事 → 从资产驾驶舱剔除，避免大杂烩。

区域与职责

  • ① 实时状态条：连接状态 + 刷新频率，物联看板必须先让人相信数据是活的
  • ② KPI 六项：接入量 / 在线率 / 今日告警 / 未闭环 / 通行 / 在场车
  • ③ 子系统在线率：定位"哪个子系统坏了"，而不是只知道总体 98%
  • ④ 告警趋势：看"什么时候坏"，用于排班与备件储备
  • ⑤ 实时告警：唯一需要人立刻响应的区块，放视觉中心
  • ⑥ 联动场景：证明物联不只"看"，还会"自动处置"

数据与口径

  • 在线率 = 最近 5 分钟有心跳的设备 ÷ 接入设备，离线阈值按设备类型可配（摄像头 3 分钟、门禁 10 分钟）
  • 告警数按告警事件计，同设备 10 分钟内重复上报合并为 1 条
  • 未闭环 = 状态非"已闭环"，含已派单、处理中
  • 通行按人次、车场按车次，口径不同不做加总
  • 能耗取网关/抄表数据，T+1 校核；异常值（环比 ±30%）标灰不参与统计

交互与规则

  • 点告警行 → 右侧抽屉：设备详情 / 历史告警 / 关联工单 / 一键派单
  • 严重告警置顶高亮，5 分钟未响应自动升级主管，与工单 SLA 共用一套计时引擎
  • 视频在线巡检：16 宫格一键轮询，人工确认画面可用——离线率高的项目必备
  • 联动场景支持 dry-run 试运行，避免"消防测试把门全开了"这类事故
  • 厂商离线时页面顶部黄条提示"车场数据延迟 12 分钟"，而不是静默显示旧数据

区域与职责

  • ① KPI 六项：编制/在岗（缺口）、试用期、异动、人力成本率、人均管理面积、待办
  • ② 招聘漏斗：投递→初筛→面试→offer→入职，看转化率与招聘周期
  • ③ 待办提醒：转正 / 合同到期 / 证书到期 / 离职交接 / 工资审核，HR 的日常就这五件事
  • ④ 部门编制：把缺口落到部门，而不是只知道总数
  • ⑤ 员工档案：一屏看全合同、社保、证书、银行卡、紧急联系人
  • ⑥ 职级与薪酬带宽：薪酬制度的骨架，调薪必须落在带宽内
  • ⑦ 工资表：应发 → 代扣 → 实发，每一笔可追溯

数据与口径

  • 人力成本率 = （工资 + 社保公积金 + 福利 + 外包）÷ 营业收入
  • 人均管理面积 = 在管面积 ÷ 在岗人数，外包按 0.5 折算（口径要写死）
  • 编制与在岗分开统计，缺口 = 编制 − 在岗，不含试用期未转正
  • 工资表锁定后不可改，只能红冲重发；个税按累计预扣法
  • 试用期、合同到期、证书有效期都以"自然日"倒计时，不按工作日

交互与规则

  • 工资表分级权限：HR 看全量，主管只看本部门且隐藏他人明细，员工只看自己工资条
  • 薪酬、身份证、银行卡加密存储，查看留痕，导出需二次审批
  • 转正/调岗/调薪/奖惩全部走 C1 审批流，HR 模块不重复造流程引擎
  • 入职自动开通账号 / 门禁 / 企微（联动 E1、D2），离职自动回收权限与门禁
  • 电子签劳动合同，到期前 60 / 30 / 7 天三级提醒
设计取舍：HR 不做成"独立系统"，做成办公域里的一个模块
为什么不做独立 HR 系统
物业公司普遍 100~300 人，独立 HR 系统的流程引擎、组织架构、权限体系与 OA 完全重叠，再买一套等于维护两份组织数据。
本设计的做法
① 组织、岗位、审批流复用 E1 与 C1；② 考勤复用 C2，只把结果接到薪酬核算；③ 人事模块只管"人"的全生命周期与钱（工资表），不做流程引擎；④ 工资表与财务凭证对接 B 费用域，人力成本进经营报表。
